# Cleanup 2026-11-23

## Root cause of the broken build
After the G815 trace analysis a second, incomplete architecture branch was added:
`g815_control`, `g815_ep82`, `usb_proxy_transport` and a reduced `p4_s3_protocol.h`
with different message IDs (ATTACH 0x12 instead of 0x20) and without OTA types.
It partially replaced the working code:

| Symptom | Cause |
|---|---|
| P4: `P4_S3_MSG_OTA_BEGIN` undeclared | reduced protocol header |
| P4: `usb_device_info_t` has no `dev_desc` | new `usb_host.c` used a non-existent field |
| S3: `p4_s3_ota_status_t` unknown | reduced protocol header |
| P4 component SRCS: 8 files only | `CMakeLists.txt` overwritten, `usb_gateway.c` etc. no longer built |
| S3 never sends STATUS | new `spi_link.c` dropped STATUS and OTA handling |
| EP82 claimed twice | `g815_ep82` claimed interface 1 although the HID host driver owns it |

## Restored architecture
- P4 owns the G815 (USB Host). Interfaces 0/1 are read by the HID host driver,
  input reports go through `g815_forwarder` to the S3.
- PC -> G815 SET_REPORT (HID++ 0x11/0x12, LEDs) goes from the S3 to the P4 as
  `p4_s3_fragment_t` and is executed on EP0 by `usb_host_control_bridge`.
- One protocol header, byte-identical on P4 and S3.

## Fixes contained
1. **Idle polling (P4 `p4_s3_link.c`)**: the P4 clocks a NOP every 2 ms when its
   queue is empty, immediately again after S3 data. Previously S3 -> P4 frames
   were only fetched while the P4 itself was sending.
2. **Report ID restore (S3 `g815_tinyusb_callbacks.c`)**: TinyUSB strips the
   Report ID from a control SET_REPORT; it is restored before forwarding, so the
   G815 receives 20 bytes (0x11) / 64 bytes (0x12).
3. **Non-blocking control path (P4 `usb_proxy_control.c`)**: USB control
   transfers run in a dedicated worker task instead of the SPI link task.
4. Atomic fragment queueing on the S3, word-aligned SPI DMA buffers.
5. S3 `CMakeLists.txt`: `WHOLE_ARCHIVE` restored (TinyUSB callback overrides).
