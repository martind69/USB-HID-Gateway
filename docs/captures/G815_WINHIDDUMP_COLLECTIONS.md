# G815 HID collection descriptors from WinHidDump

Capture source: user-supplied `Eingefügter Text(3).txt`, generated by `winhiddump.exe`.
Device: Logitech G815 RGB Mechanical Gaming Keyboard, VID/PID `046D:C33F`.

## Important interpretation

WinHidDump lists Windows HID collection handles (`MI_xx&colxx`) and the report descriptor returned/reconstructed for each handle. These are **collection-level descriptors**, not necessarily byte-for-byte copies of the complete HID Report Descriptor returned by USB `GET_DESCRIPTOR(Report)` for the corresponding interface.

The USB configuration capture previously recorded:
- Interface 0 report descriptor length: 65 bytes.
- Interface 1 report descriptor length: 188 bytes.

The collection descriptors below are preserved exactly as printed by WinHidDump. Their lengths must not be substituted for the interface-level lengths above, and the collection descriptors must not be concatenated and presented as the original 65-/188-byte interface descriptors.

The output also contains a separate Windows `HID VHF Driver` device with VID/PID text `046D:C33F` and a 460-byte descriptor. It is a Windows virtual HID node (`hid_device_system_vhf`), not the physical Logitech USB interface. It is therefore excluded from the physical G815 descriptor set.

## Preliminary report-level interpretation

The two vendor-defined collection descriptors are particularly relevant:

- Collection 4 uses Report ID `0x11` and declares `0x98` bits = 19 bytes of report data. With the Report ID byte, this corresponds to a 20-byte report.
- Collection 5 uses Report ID `0x12` and declares `0x1F8` bits = 63 bytes of report data. With the Report ID byte, this corresponds to a 64-byte report.

These sizes align with the observed G815 vendor interrupt endpoint maximum packet size of 64 bytes and the additional 20-byte report size observed in the collection descriptor. Actual endpoint/report routing must still be confirmed against the USB interface descriptor and captured transfers; HID report size does not itself prove which endpoint carries each report.

The keyboard collection (interface 0), consumer-control collection, pointer-like collection and vendor-defined collections must be considered separately when implementing the Windows-visible HID collection behavior. The physical USB device still enumerates as one G815 device with its USB interfaces; Windows collection handles are not additional physical USB devices.

## Implementation constraints

1. Preserve the exact bytes above as WinHidDump collection-descriptor evidence.
2. Do not use the 460-byte VHF descriptor as the G815 physical USB descriptor.
3. Do not concatenate these collection descriptors to fabricate the original 65-byte or 188-byte interface report descriptors.
4. Before implementing the CH552 USB descriptors, obtain the raw interface-level Report Descriptor bytes from USB `GET_DESCRIPTOR(Report)` responses or another source that preserves the original interface descriptor byte stream.
5. Use the collection-level descriptors to map Report IDs, usages and report lengths, and cross-check them against actual interrupt/control traffic.
6. Recalculate CH552 endpoint RAM and ROM only after the intended USB descriptor representation and endpoint-buffer allocation have been implemented and compiled.

No firmware compilation, memory measurement, flashing, USB enumeration or G HUB compatibility test is claimed by this document.
