# Logitech G815 — USB descriptor evidence

Status: **partially captured; raw interface-level HID Report Descriptors are still missing**.

Device: Logitech G815 RGB Mechanical Gaming Keyboard  
VID/PID: **046D:C33F**  
Evidence scope: physical USB device only. Windows-created virtual HID nodes are excluded.

This is the central byte-level evidence record. It distinguishes:
1. Raw USB Configuration Descriptor and its interface/HID/endpoint descriptors.
2. Windows HID collection descriptors reported by WinHidDump.
3. Missing raw interface-level HID Report Descriptor byte streams.

Do not treat category 2 as a substitute for category 3. Do not synthesize missing bytes.

## 2. Raw interface-level HID Report Descriptors — missing evidence

The original physical USB Report Descriptor byte streams have **not** yet been captured as complete, independently verified data-stage payloads:

| Interface (wIndex) | GET_DESCRIPTOR wValue | Declared wLength | Evidence status |
|---:|---:|---:|---|
| 0 | 0x2200 | 65 | Missing |
| 1 | 0x2200 | 188 | Missing |

Required SETUP fields:

- bmRequestType = 0x81 — Device-to-host, Standard, Interface
- bRequest = 0x06 — GET_DESCRIPTOR
- wValue = 0x2200 — Report Descriptor, descriptor index 0
- wIndex = 0 or 1 — interface number
- wLength = 65 or 188 — declared descriptor length

Reassemble the control-transfer data stage in packet order. Export only the data-stage payload; exclude SETUP, status stage, USBPcap pseudo-header and packet headers. Verify final payload length against wLength.

Expected evidence files:
- g815_interface0_report_descriptor.hex — exactly 65 bytes
- g815_interface1_report_descriptor.hex — exactly 188 bytes

Retain the source PCAPNG and record SETUP/completion frame numbers. See [raw capture procedure](G815_REPORT_DESCRIPTOR_CAPTURE.md).

**Do not** concatenate the WinHidDump collection descriptors in section 3 to create either missing stream. Candidate arrays previously discussed are provisional, not byte-exact evidence.

## 4. Excluded Windows virtual HID descriptor

The WinHidDump output also contains a 460-byte descriptor associated with hid_device_system_vhf / Microsoft HID VHF Driver. This is a Windows virtual HID node, not the physical G815 USB interface descriptor. It is excluded from the physical-device evidence above.

## 5. Evidence interpretation and implementation constraints

1. The 59-byte Configuration Descriptor is captured raw and is the source for the interface, HID descriptor and endpoint properties in section 1.
2. The 50-/28-/74-/56-/32-/33-byte streams are WinHidDump collection-level evidence only.
3. The physical interface-level Report Descriptor lengths are 65 and 188 bytes, but their original byte streams remain missing.
4. Do not substitute, concatenate, normalize or silently edit collection-level descriptors to fill the missing raw streams.
5. The keyboard collection's 50-byte Windows descriptor differing from the interface 0 declared length of 65 bytes is an observed distinction, not evidence that either value should be changed.
6. G HUB compatibility is not established by VID/PID, descriptors or report sizes alone. Vendor control transfers, Feature/Output reports, interrupt traffic, enumeration topology and application behavior require separate testing.
7. In the current architecture, the G815 is emulated by the secondary ESP32-S3. Descriptor implementation remains provisional until the missing raw report descriptors and required runtime traffic have been validated.
